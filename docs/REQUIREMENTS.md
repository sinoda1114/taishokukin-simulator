# 退職金シミュレーター 要件定義（ドラフト v0.1）

作成日: 2026-09-20
ステータス: v0.5（楽天証券 出口戦略 2動画の論点を追加。2026-09-20 決定: フルスタック構成・Turso・Clerk 後付け。「12. 決定事項」「14. アーキテクチャ」「15. データモデル」参照）

---

## 1. 目的・背景

退職金（会社退職金・企業年金）と iDeCo/企業型DC の一時金は、いずれも「退職所得」として大きな税優遇を受ける。
しかし **受け取るタイミング（年）と順序** によって、退職所得控除の重複調整ルールが働き、税額が数十万〜百万円単位で変わる。
さらに **2026年1月1日以降**、iDeCo一時金を先に受け取ってから退職金を受け取る場合の調整対象期間が「前年以前4年内」から「前年以前9年内」に延長された（いわゆる「5年ルール → 10年ルール」）。

本シミュレーターは、ユーザーの勤続年数・iDeCo加入期間・受取予定額・受取年齢を入力すると、
**受取パターンごとの税額・手取りを正確に計算し、最も有利なタイミングを提示する** ことを目的とする。

参考にした解説（お手本）: 脱税理士スガワラくん「5年ルールが消えた後に最もお得に退職金を受け取る方法」
（https://www.youtube.com/watch?v=QUPgDYWWEUI）。ただし動画は概算・省略が多いため、本仕様は一次情報（所得税法・国税庁タックスアンサー）を正とする。

## 2. 対象ユーザー・ユースケース

| ユーザー | ユースケース |
|---|---|
| 50〜65歳の会社員（iDeCo 加入者） | 退職金と iDeCo をいつ・どの順で受け取ると手取り最大か知りたい |
| 個人事業主（小規模企業共済 + iDeCo） | 共済と iDeCo の受取順序を比較したい（v2） |
| FP・税理士 | 顧客説明用に数値の根拠を示したい（計算過程の表示が必要） |

## 3. スコープ

### 3.1 MVP（v1）
- 退職手当等 **N本**（会社退職金、iDeCo/企業型DC一時金、DB一時金、小規模企業共済、前職退職金 など）。UI 上の上限は 6本程度
- 一時金受取のみ（年金受取は v2）
- 受取パターン比較: 全手当等を同年一括 / 順序を変えた組み合わせ（2本なら「同時 / 退職金先 / iDeCo先」の3パターン）
- 法制度の切替: 2025年以前ルール（4年内）/ 2026年以降ルール（9年内）
- 最適タイミング探索: 受取年を動かせる手当等（iDeCo は 60〜75歳、共済は任意解約可能年以降 など）について全探索し、合計税額最小を提示
- 計算過程（控除額・重複調整・課税退職所得・税額内訳）の表示
- 一般公開前提: 免責表示、OGP、最低限の SEO、スマホ対応
- シミュレーション結果の保存と共有 URL（匿名でも可、後からアカウントに紐付け可能）
- 税率・制度テーブルを DB で管理（管理画面からの更新は v2、MVP は seed + 管理者 API）
- 匿名の利用ログ・統計
- 認証（Clerk / Google のみ）は **後付け**。MVP では認証境界だけ用意し、無効化した状態で機能検証する

### 3.2 v2 以降（候補）
- iDeCo 年金受取（雑所得・公的年金等控除: 65歳未満 60万 / 65歳以上 110万 が目安）との比較
- **併用の最適化**: 一時金を「退職所得控除の残枠ぴったり」まで受け取り、残りを年金で受け取る案の自動提示
- 年金受取のルール: 受取開始 60〜75歳、受取期間 5〜20年。公的年金の繰下げ（最大1.84倍）との組み合わせ
- 年金受取時の社会保険料（国保・介護）への影響
- 企業型DC を移換せず年金で受け取り、iDeCo 加入を 70歳まで続ける案（2026年12月改正後）
- 公的年金等控除の具体値（65歳未満 60万 / 65歳以上 110万、他の所得により変動）と、公的年金繰下げ（1か月 +0.7%、70歳 1.42倍、75歳 1.84倍、損益分岐は概ね受取開始 +12歳）を組み合わせた受取タイミング比較
- 年金受取の運用元本按分（残存回数按分）、受取回数、受取手数料（運用指図者 66円/月、給付 440円/回 など）の概算
- **入口の節税効果を含めたトータル比較**: 掛金の所得控除による節税累計（年収→限界税率）と運用益非課税を加味し、出口の税額と差し引きで NISA 等と比較（F16）
- 年金で受け取った分は退職手当等に該当せず重複調整の対象外になる、を併用計算に反映
- 退職所得の受給に関する申告書 未提出時の源泉（20.42%）の注意喚起
- 結果の URL 共有（クエリパラメータに状態を持たせる）

### 3.3 対象外
- 個別の税務相談・断定的な助言（免責表示を出す）
- 確定申告書の生成
- 個人情報の収集（氏名・住所・口座等）。保存するのは試算の入力値と結果、および Clerk のユーザー ID のみ
- 計算そのものはサーバーに依存させない（計算エンジンはブラウザでもサーバーでも動く純関数）

## 4. 用語

| 用語 | 意味 |
|---|---|
| 退職手当等 | 会社退職金、企業年金一時金、iDeCo/企業型DC 老齢一時金、小規模企業共済 一括受取 など、退職所得扱いの収入 |
| 勤続年数 | 退職所得控除の計算に使う年数。1年未満の端数は **切り上げ** |
| DC一時金 | 確定拠出年金（iDeCo・企業型）の老齢給付金を一時金で受け取るもの。勤続年数 = 掛金拠出期間（通算加入者等期間） |
| 重複期間 | 2つの退職手当等の勤続期間が重なる期間 |
| 調整対象期間 | 前の退職手当等を受けた年が、今回受取年の「前年以前N年内」なら重複調整を行う。N は順序と時期で変わる（5. 参照） |

## 5. 計算仕様（計算エンジン要件）

### 5.1 退職所得控除額（基本）
- 勤続年数 ≤ 20年: `40万円 × 勤続年数`（80万円未満なら 80万円）
- 勤続年数 > 20年: `800万円 + 70万円 × (勤続年数 − 20)`
- 勤続年数の端数（月・日）は切り上げ
- 障害者になったことが直接の原因で退職した場合: `+100万円`
- **勤続期間は連続とは限らない**（例: 企業型DC 23年 → 運用指図者 10年（除外）→ iDeCo 5年）。各退職手当等は勤続期間を **区間の集合** として持ち、勤続年数はその合計で計算する。重複判定も区間同士の交差で行う

### 5.2 課税退職所得金額
- 原則: `(収入金額 − 退職所得控除額) × 1/2`（1,000円未満切り捨て）
- **特定役員退職手当等**（役員等としての勤続年数が5年以下の部分）: 1/2 を適用しない
- **短期退職手当等**（役員以外で勤続年数5年以下）: 控除後の金額のうち 300万円を超える部分は 1/2 を適用しない
- **MVP では特定役員・短期は計算対象外**とし、勤続5年以下の入力があれば注意書きを表示する。計算エンジンには適用フラグの拡張ポイントだけ残す（決定事項 Q4）

### 5.3 税額
- 所得税: 課税退職所得金額に **所得税の速算表**（5〜45%、7段階）を適用
- 復興特別所得税: 所得税額 × 2.1%（2037年まで）
- 住民税: 課税退職所得金額 × 10%（市町村民税6% + 道府県民税4%。100円未満切り捨て）
- 合計税額と手取り（収入 − 税額）を出す
- 分離課税のため他の所得とは合算しない（年金受取比較を入れる v2 で初めて総合課税が絡む）

### 5.4 同一年に複数の退職手当等を受ける場合
- 同じ年に受けた退職手当等は **合算して1つの退職所得** として計算する
- 勤続年数は、各勤続期間を合わせた期間（重複部分は二重に数えない）で計算する

### 5.5 前年以前に他の退職手当等を受けている場合の重複調整（本シミュレーターの核心）

今回受け取る退職手当等を「本年分」、過去に受け取ったものを「前の退職手当等」と呼ぶ。

**(a) 調整が発動する条件（調整対象期間）**

| 本年分の種類 | 前の退職手当等の種類 | 調整対象期間 | 備考 |
|---|---|---|---|
| 一般の退職金 | 一般の退職金・共済など | 前年以前 **4年内** | 従来どおり |
| 一般の退職金 | **DC一時金** | 前年以前 **9年内** | **2026年1月1日以降の支払分から**。2025年12月31日以前は 4年内 |
| **DC一時金** | 何であれ | 前年以前 **19年内** | 令和4年改正で 14年→19年 |

「前年以前N年内」は **年単位** で判定する（例: 2030年に受け取る場合、4年内 = 2026〜2029年）。
同じ年なら 5.4 の合算扱い。

**N本ある場合の扱い**
- 本年分ごとに、それより前に受け取った全ての退職手当等を「前の退職手当等」として評価する
- 対象期間 N は **前の退職手当等ごとに、その種類（DC一時金か否か）で判定**する（例: 本年分が一般退職金のとき、5年前の DC一時金は 9年内で対象、5年前の共済は 4年内で対象外）
- 重複期間は、対象となった前の退職手当等の勤続期間の **和集合** と本年分の勤続期間との重なりで求める（二重に引かない）
- 前の退職手当等が同一年に複数ある場合は、その年分をまとめて 1つの前の退職手当等（合算収入・合算期間）として扱う（東京国税局 文書回答 2024-03-22 参照）
- 小規模企業共済の一括受取は「一般の退職金」と同じ扱い（DC ではない）

**(b) 調整の内容**
- 本年分の勤続期間と、前の退職手当等の勤続期間との **重複期間** を求める
- 本年分の退職所得控除額 = `通常の控除額（本年分の勤続年数ベース） − 重複期間の年数で計算した控除額`
  - 「重複期間の年数で計算した控除額」は、重複年数を勤続年数とみなして 5.1 の式（20年以下は40万×年数、超過分は70万×年数）で計算する（所得税法施行令70条）
  - よって非重複部分の実効単価は 70万/40万/その混合のいずれにもなり得る。例: 拠出33年（控除1710万）で重複25年（1150万）なら 560万、重複15年（600万）なら 1110万
  - 「全体の勤続年数から重複年数を引いてから控除を計算する」方式は **誤り**。テストで排除する
- 重複期間の年数の端数は **切り捨て**（本年分の勤続年数は切り上げ、と非対称なので注意）
- 調整後の控除額が 80万円未満なら **80万円**（動画の「0の場合は80万」はこれ。完全重複でも 80万円は残る）

**(c) みなし勤続期間（前の退職手当等が控除額に満たなかった場合）**
- 前の退職手当等の収入金額 < その勤続年数で計算した控除額 のとき、前の勤続期間は
  「初日から、`収入金額 ÷ 40万円`（20年超部分は 70万円）で逆算した年数（1年未満切り捨て）を経過した日の前日まで」とみなして重複期間を計算する
- 例: iDeCo 一時金 500万円・加入20年（控除800万円）の場合、みなし勤続年数 = 500 ÷ 40 = 12年。重複は最初の12年分だけで判定
- 動画では触れられていないが、iDeCo 資産が控除額より小さいケースは多いため **MVP で必須**

**(d) 期間の入力と重複判定**
- 各退職手当等について「勤続（加入）開始年月」「終了年月」を持ち、月単位で重複期間を求める
- 簡易入力（勤続年数のみ）も許容し、その場合は「終了 = 退職年、開始 = 終了 − 年数」で期間を復元する

### 5.6 iDeCo 固有の制約
- 受取開始可能年齢: 60〜75歳（通算加入者等期間が10年未満の場合は繰り下がる: 8年以上→61歳 … 1月以上2年未満→65歳）
- 一時金・年金・併用が選べる（MVP は一時金のみ）
- 勤続年数 = 掛金を拠出した期間（運用指図者期間は含まない）。企業型DC → iDeCo 移換の場合は企業型DC の加入者期間と iDeCo の加入者期間を **通算**する
- 退職後も iDeCo に掛金を拠出し続けると勤続年数が伸び、控除額が増える（出口戦略の主要テクニック。シミュレーターは「拠出終了年齢」を動かして効果を見せる）
- **2026年12月改正（予定）**: 加入可能年齢が 70歳未満まで拡大（第5号加入者）、掛金上限 月6.2万円。老齢基礎年金または iDeCo の老齢給付金を受給すると加入不可。厚生年金・企業年金の受給は加入の妨げにならない。拠出終了年齢の上限は制度施行日で切り替える
- 企業型DC を iDeCo に移換せず企業型のまま一時金/年金で受け取れば、iDeCo 加入は継続できる（移換して iDeCo の老齢給付を受けると拠出不可）。注意書きとして表示

### 5.7 2026年改正の切替
- 支払を受ける日が 2026-01-01 以降かどうかで 5.5(a) の「4年内/9年内」を切り替える
- UI でも「改正前/改正後」を明示し、両方の結果を並べて見られるようにする

## 7. 出力項目

- パターンごとの一覧表: 受取年、控除額（調整前/調整後）、課税退職所得、所得税、復興特別所得税、住民税、合計税額、手取り
- 推奨パターン（税額最小）と、その次善策、および「同時受取との差額」
- 計算過程の展開表示（FP・税理士の説明用。数式と代入値を出す）
- iDeCo 受取年齢を横軸にした税額グラフ（60〜75歳）
- 注意書き: 改正の適用時期、申告書提出前提、年金受取は未対応、免責

## 9. 非機能要件

- **正確性が最優先**: 計算エンジンは UI から分離した純関数群とし、国税庁の設例・動画の設例をテストケースとして固定する（TDD）
- **計算エンジンの DB 非依存**: テーブルは DB から読むが、エンジンは引数で受け取る。テストは JSON seed だけで動く（DB 不要）
- **認証なしで全機能を検証可能**: `AUTH_PROVIDER=none` で E2E を回す。Clerk は環境変数で後から有効化
- **プライバシー**: 保存する入力は金額・年月・種類のみ。利用ログは匿名化し、プライバシーポリシーを掲示
- **端数処理**を仕様どおりに実装し、テストで担保
- **税率テーブル・閾値はデータとして外出し**（税制改正時にコード変更を最小にする）
- スマホ幅で使える（320px〜）
- 免責表示（試算であり税務助言ではない）

## 10. 動画（お手本）との差分・動画側の誤り

計算エンジンの正としては以下を採用する。

1. **復興特別所得税（2.1%）が動画では省略**されている。本仕様では含める
2. **動画パターン2（退職金65歳→iDeCo70歳）の iDeCo 側の税額「約49万」は所得税のみ**で住民税46万が抜けている。正しくは約96万、2パターン合計は約90万ではなく **約137万**。「同時受取の半分」にはならない（それでも同時受取より有利なのは変わらない）
3. **みなし勤続期間（5.5(c)）**の説明がない。iDeCo 資産 < 控除額 のときに結果が変わる
4. 動画は勤続20年と iDeCo 20年が完全に重複する前提だが、実際は **開始・終了年月で部分重複** を計算する必要がある
5. **2026年以降の iDeCo先→退職金後（5年空け）**は動画の言うとおり調整が入る。試算では重複20年で控除が 1500万→700万 に減り、合計税額は約169万（同時受取 約186万 とほぼ同水準）。この場合 **退職金先→iDeCo後（19年ルール）のほうが有利になり得る**ので、順序の優劣は固定ではなくシミュレーターで比較させる
6. 「19年以上空ける」のは正確には **「前年以前19年内に他の退職手当等がない」**（= 20年空ける）。年単位判定であることを明記する
7. 動画で触れていない: 特定役員・短期退職手当、障害退職加算、端数切り上げ/切り捨て、iDeCo の受取開始年齢制限、年金受取の選択肢

### 10.2 第2のお手本（楽天証券「出口戦略 / 転職・移換」動画）から取り入れた点

1. 重複調整は「控除額同士の差」であり「年数の差」ではない、を明文化（5.5(b)）。誤解が多い箇所なので UI の計算過程でも式を見せる
2. 勤続期間を区間の集合で扱う（転職・移換・運用指図者期間を表現できる）（5.1、6）
3. 企業型DC と iDeCo の加入者期間の通算、退職後の iDeCo 拠出継続による控除増（5.6）
4. 2026年12月の iDeCo 加入年齢拡大（70歳未満）と受給制限（5.6）
5. 「退職金だけで控除を使い切っている人」の同時受取が最も不利、という判定メッセージを結果に添える（F14）
6. v2 の年金受取に「控除残枠ぴったり一時金 + 残り年金」の併用最適化を追加（3.2）
7. 転職 3本ケース（退職金→iDeCo→退職金2）をテストケース化（T9）

対象外として明記: 自動移換の手続き案内、マッチング拠出と iDeCo の併用可否などの制度手続き（注意書きリンクのみ）

### 10.3 第3のお手本（楽天証券「iDeCo 出口戦略 総合版」）から取り入れた点

1. 「1年ずらし」設例（退職金60歳 → DC 61歳、運用指図者1年）をテストケース化（T11）。80万下限と税率差の 2 効果で差が出ることを計算過程で説明する
2. みなし勤続期間の具体設例（退職金800万・勤続35年 → みなし20年 → 重複10年）をテストケース化（T12）。みなし期間は勤続期間の **初日から** 数える
3. 「同時受取が有利になるケースもある」。シミュレーターは順序の優劣を断定せず、全パターンを計算して並べる（既存方針の再確認）
4. 退職後の iDeCo 拠出は **最低額（月5,000円）でも控除の伸びは同じ**（控除は期間に依存し金額に依存しない）。解説メッセージ候補に追加（F14）
5. 入口の所得控除・運用益非課税を含むトータル比較を v2 候補に追加（F16）
6. 年金受取の具体ルール（5〜20年、按分、手数料）と公的年金繰下げ倍率を v2 要件に数値で追加
7. 個人年金保険は公的年金等控除の対象外。v2 の年金比較で混同しないよう対象外を明記

## 14. アーキテクチャ（既定案）

```
Browser (Next.js App Router, React)
   │  入力フォーム・比較表・グラフ。計算はクライアントでも即時実行（体感速度）
   ▼
Route Handlers / Server Actions (Next.js)
   │  保存・共有・履歴・ログ・税率テーブル配信。認証境界 getCurrentUser()
   ▼
Drizzle ORM ── @libsql/client ── Turso (libSQL)
```

- `packages/engine`（または `src/engine`）: 純 TS の計算エンジン。入力 + 税率テーブル → 結果。DB・React 非依存。ここを TDD で固める
- `src/app`: UI と Route Handlers
- `src/db`: Drizzle スキーマ・マイグレーション・seed（税率テーブルの初期値は JSON で管理し seed で投入）
- `src/auth`: `getCurrentUser()` の実装切替（none / clerk）。Clerk 導入時は middleware と Provider を追加するだけで済むよう、ページ側は `getCurrentUser()` の戻り値だけを見る
- 匿名ユーザーの保存: share token（推測困難な ID）で行い、後で Clerk ログイン時に `claim` して owner を付け替える

代替案: Cloudflare Workers + Hono + Turso。Vercel/Next.js より軽いが Clerk との統合手間が増えるため既定にしない。

## 15. データモデル（初期案。コミット前にスキーマ承認を取る）

| テーブル | 主な列 | 備考 |
|---|---|---|
| `users` | id, clerk_user_id (unique, nullable), created_at | Clerk 導入前は行を作らない |
| `simulations` | id, share_token (unique), owner_user_id (nullable FK), title, input_json, result_json, ruleset_version, created_at, updated_at | 匿名保存は owner null。claim で owner を付与 |

- `tax_rulesets.payload_json` の形はエンジンの `TaxRuleset` 型と一致させ、Zod で検証してから使う
