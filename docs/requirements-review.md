## 判定

**だいたい合っている。** 作るもの（一時金の受取年・順序で退職所得の税額を並べる Web シミュレーター）、計算の芯（重複調整は控除額の差、みなし勤続、4/9/19年、法令が動画より正）、MVP の輪郭（一時金のみ・N本・認証後付け・フルスタック）は一貫している。残るのは文書の残骸と、エンジンを書く前に一意にならない数か所である。方向のやり直しは不要。

## 合っている点（短く）

- 主対象は 50〜65歳の会社員（iDeCo）。FP は同一画面の計算過程。共済は種類として v1、個人事業主ユースケースは v2。
- エンジンは純関数。クライアント即時計算とサーバー保存は両立する、でよい。
- 令和4年の 19年ルールと 2026年の 4年→9年は別レイヤ、切替キーは支払を受ける日、で読めている。
- 必須機能の芯は F1（税額）・F5（過程）・F8（N本調整）・F3（探索）。F6 保存、F10 税率テーブル、F9 公開面は製品として載せる、でよい。
- Q5 / 冒頭ステータス / §14 がフルスタックの正。Q1 の静的 SPA は撤回漏れ。
- 空白 58 件のうち大半は画面分割・コピー・保持期間など、エンジンより後で決められる。

## Must（塞がないと作れない）

批評の Must 16件は、全部がブロッカーではない。ここでは「決まらないと F1 / F5 / F8 の計算、または F6 の MVP 切片が二通りになる」ものだけ残す。**8件。**

1. **構成の正本。** Q1（静的 SPA）を撤回し、Q5 / §14 に一本化する。残したままだと F6 / F10 / F11 / F12 を載せるかどうかを実装者が選べてしまう。
2. **F6 の MVP 切片。** 必須は匿名 share token による保存・共有まで。履歴一覧・再編集・claim は Clerk 導入後（F12 の `AUTH_PROVIDER=none` と両立させる）。§3.2 のクエリ共有は v2 のまま残し、MVP の共有は token のみ。
3. **端数処理とテストの正。** `(収入−控除)` と `×1/2` と 1,000円切捨ての順、所得税・復興税の円未満、住民税 10% を合算後に 100円切捨てるか 6%+4% 別々か、を決める。そのうえで T1〜T4 を確定値にする。T5 は空欄、T8 / T11 / T13 は復興税抜きの動画値なので、オラクルにするか参考値にするかを分ける。ここが空だと F1 / F5 のテストが正にならない。
4. **みなし勤続の「控除額」と T9。** §5.5(c) の「その勤続年数で計算した控除額」が調整前か、前の手当等自身の調整後かで、T9 の「退職金2 と重複5年」が出たり出なかったりする。F8 と T9 を同時に正にできない。
5. **みなし逆算の式と、日条文の月近似。** 20年超（800万超）の ÷70万、収入 80万未満、逆算 0 年。条文の「経過した日の前日まで」を月区間へ落とす規則。例示は ÷40万 だけなので、T5 / T12 以外が書けない。
6. **同一年に DC と一般が混在する塊の種類。** §5.5(a) は前の手当等ごとに DC か否かで 4/9/19 年を見る。同じ節で同一年は 1つの前の手当等にまとめる。まとめた塊に種類が無いと、翌年以降の窓が決まらない。N本が必須なので「2本なら起きない」では済まない。
7. **区間と勤続年数の月次規則。** 終了月の inclusive、月数→年の切り上げ境界、簡易入力の開始月・終了月。T6（20年3か月 → 21年）が再現できない。入力は年、区間は `YYYY-MM`、みなしは日、が三層のまま。
8. **重複期間の控除に 80万下限を掛けない、を式で固定する。** 本文は「5.1 の式」と書き、5.1 には 80万下限がある。例（重複15年 = 600万）は下限を掛けていない。下限を重複側に入れると F1 の式が壊れる。理解は例の側でよい。本文を例に合わせる。

表題 v0.1 / ステータス v0.5 は正本を v0.5 に揃える（ブロッカーではないが、直すのは Must 1 と同じ作業）。

## Should（あると迷わない。後でも製品は動く）

- **管理者 API は MVP では出さない。** seed のみ。一般公開かつ認証オフで税率更新 API は置けない。F13 まで待つ。
- **F2 は「会社退職金1 + DC1」の既定3行。** N本の本体は F3。実現不能（会社退職が 60歳未満固定で iDeCo 先が取れない等）は出さない。「同時との差額」の同時年は、固定側の受取年。
- **F3 の上限・超過・同税額。** 粒度は暦年。上限は仮置きしてよい。超過は打ち切りを明示。同税額は受取が早い順など、どれか一つ。
- **F15。** 見込み額は固定、動かすのは拠出年数だけ。拠出終了 ≤ 受取。受給後拠出は除外。被保険者資格は注意書き。
- **F4。** 切替は本年分の支払年。入力が年だけなら 2026年受取 = 改正後。「改正前固定 / 改正後固定」は反実仮想。年またぎ探索では年ごとに窓を変える。
- **種類。** 「その他」は一般扱い。企業型と iDeCo は 1本の区間集合が既定。別年で受け取るなら 2本。DB 一時金は確認質問。
- **勤続5年以下。** Q4 どおり特定役員・短期は計算しない。出すなら 1/2 付きの仮計算だとは書かず、警告の強さだけ決める（確認質問 10）。
- **障害 +100万** は当該手当の通常控除に足してから重複減算。重複側の控除には入れない、で足りる。
- **保存の正** はサーバ再計算。画面は `ruleset_version` 付き。旧保存は当時の ruleset で再現。
- **探索の目的関数** は合計税額最小。収入が同じなら手取り最大と同じ。F15 で額が変わらない前提なら衝突しない。
- **通算加入者等期間** が入力に無いので、受取開始下限は 60歳 + 注記に落とす。
- **対象外を明記:** 非居住者、死亡一時金、分割支給。共済の任意解約が退職所得にならない場合は、扱うなら注意、扱わないなら種類から外す。
- **復興税は 2037年まで。** 2038年以降の受取は 0。`tax_rulesets` に終了日を持たせる。
- **公開面。** 免責は入力前と結果と共有ページ。「推奨 / 最適」は「税額最小の試算」。OG に金額を出さない。共有は `noindex`。PP / 規約 / 運営者表示。§10 の動画名指しは公開ページに出さない。
- **F14** は任意のまま。§10.2 の判定メッセージは、入れるなら F14 を必須に上げる。今は上げない。
- **T7** は「MVP 簡易。短期退職手当等は未適用」。
- **token** は推測困難、閲覧は URL を知った人、第三者 claim は禁止、削除と保持期間は後でよい。
- **本番で `AUTH_PROVIDER=none` を拒否。** 画面 IA・320px の表の折り方は空白のままでエンジンを止める理由にしない。

## 篠田さんへの確認質問

実装者や一次情報で埋められるものは上に回した。ここは意図が割れるものだけ。**10件。**

1. Q1 は撤回でよいか。正本は Q5 / §14 か。
2. F6 の履歴・claim は Clerk 導入後でよいか。MVP の共有は share token のみ（クエリ方式は v2）でよいか。
3. みなしの「控除額」は、その手当等の調整前か調整後か。T9 をどちらに直すか。
4. 同年に DC と一般が混在するとき、翌年以降はどの種類で 4/9/19 年を見るか。
5. F2 は「会社退職金1 + DC1」のときだけか。
6. 勤続・重複は月近似でよいか（施行令の「日の前日」を月に落とす）。
7. iDeCo 探索の「60歳」は、その年に誕生日を迎える暦年か。
8. F15 は見込み額固定でよいか。2026年12月の加入年齢拡大は MVP に入れるか、注意書きか、入れないか。
9. 共済の任意解約を、MVP では退職所得として扱ってよいか。対象外か。
10. 勤続5年以下は、計算せず警告だけか、1/2 付きの仮計算＋強い警告か。
